Troubleshoot Slow DNS Response

Use Copilot, web-probe metrics, and Y-Engine to validate DNS latency as the root cause.

Time: ~15 minutesTasks: 4Outcome: Slow DNS confirmed as the root causeEnvironment: SDC · read-only

16.1

Use ZDX Copilot for Root Cause Analysis

Ask ZDX Copilot to analyze Linda Lucas’s consistently poor SaaS experience.

Current Experience Center navigation
Digital Experience

Fastest option: use Search menu and search for Copilot.

  1. In Digital Experience use Search menu for Copilot.
  2. Ask: Linda Lucas linda.lucas@thexerotrustlab.com reports to the service desk that she is having a consistently poor experience when accessing SaaS apps like okta. analyze the reason behind
  3. Review the response and note any references to DNS latency, Page Fetch Time, or other likely root causes. You will validate these findings manually in the remaining tasks.
✓
Expected result

Copilot proposes one or more likely causes that can be tested against ZDX telemetry.

16.2

View the User ZDX Score Over Time

Open Linda’s user/device report and review her ZDX score over the incident period.

Current Experience Center navigation
Digital Experience

Fastest option: use Search menu and search for User/Device Search.

  1. Use Search menu for User/Device Search. Search User = Linda Lucas, Device = HOST-2.
  2. Set the incident window to about 48 Hours and review ZDX Score Over Time across monitored applications.
  3. In the source scenario the score remains consistently Poor and all applications are low-scoring; use the current SDC data rather than expecting exact values.
✓
Expected result

You have a clear poor-experience interval for Linda/HOST-2 to analyze.

16.3

Analyze High Page Fetch Time

Break Page Fetch Time into its components and determine whether DNS is dominating the delay.

Current Experience Center navigation
Digital Experience
  1. In Linda’s report scroll to Web Probe Metrics and review the range of Page Fetch Time.
  2. Select a sample and compare Page Fetch Time against its baseline.
  3. Inspect the Page Fetch Time breakdown, especially Server Response Time and DNS Resolve Time.
  4. Look for large DNS Resolve Time values or strong fluctuations that account for most of the total page-load delay.
✓
Expected result

The selected samples show whether DNS resolution is the dominant component of the slow page fetch.

16.4

Confirm the Root Cause with ZDX Analysis

Use Y-Engine to confirm the root cause and identify the DNS server involved.

Current Experience Center navigation
Digital Experience
  1. Return to ZDX Score Over Time for Linda/HOST-2 and click Analyze Score.
  2. Review the contributing factors and confidence level. Compare the result with your Task 16.3 Web Probe findings.
  3. In User Devices, identify the DNS server used by HOST-2. The source scenario shows 10.0.1.53.
  4. Conclude whether the Copilot, Page Fetch Time breakdown, and Y-Engine independently point to the same DNS root cause.
✓
Expected result

Manual telemetry and Y-Engine confirm (or refute) slow DNS as the primary cause of Linda’s poor SaaS experience.

✓
Lab 16 complete

Slow DNS confirmed as the root cause
