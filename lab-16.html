Troubleshoot Slow DNS Response

Use ZAgent and ZDX probe data to investigate persistent SaaS slowness and verify DNS latency as a possible root cause.

Time: ~15 minutesTasks: 4Outcome: Slow DNS confirmed as the root causeEnvironment: SDC · read-only

Solutions Demo Center — read only

Labs 14–16 use the pre-configured SDC tenant, not your learner tenant. Complete the SDC access checkpoint before continuing. Do not create or modify configuration unless a lab step explicitly instructs you to.

16.1

Use ZAgent to Investigate Slow SaaS Performance

Ask ZAgent for a hypothesis before reviewing user-level metrics.

Experience Center · find this resource

Search Menu → ZAgent

  1. From Experience Center, select ZAgent in the upper-right corner. Choose Agent (@): Digital Experience and Skill (/): Troubleshooting.
  2. Submit this investigation prompt:
    Investigation prompt

    Linda Lucas (linda.lucas@thezerotrustlab.com) reports consistently poor SaaS performance over the last 48 hours, particularly for Okta. Analyze the likely cause.

  3. Review ZAgent’s answer. Record any mention of DNS resolution, Page Fetch Time, and latency. Treat this as a hypothesis to verify, not a confirmed diagnosis.
✓
Expected result

You have a testable hypothesis about Linda’s poor SaaS experience.

16.2

Review User ZDX Score Over Time

Confirm the reported symptoms and incident timeframe.

Experience Center · find this resource

Search Menu → Users Overview

  1. Select View User Details in ZDX from ZAgent’s response. Inspect user Linda Lucas and device HOST-2.
  2. Set the time range to 48 Hours, select application Okta, and apply the filter.
    FilterValue
    Time range48 Hours
    ApplicationOkta
    UserLinda Lucas
    DeviceHOST-2
  3. Review ZDX Score Over Time. Look for consistently Poor scores and identify the interval for deeper analysis.
✓
Expected result

You have identified the affected user, device, application, and time window.

16.3

Identify the High Page Fetch Time Component

Separate DNS delay from server and application delays.

Experience Center · find this resource

Search Menu → Web Probe Metrics

  1. In Linda’s device report, open Web Probe Metrics → Page Fetch Time. Compare recent values with the baseline.
  2. Select a high-latency sample and inspect its timing breakdown. Compare DNS Resolve Time with server processing or response time.
  3. Determine whether DNS resolution explains the majority of the delay. Exact sample values vary across SDC sessions.
✓
Expected result

You can identify whether DNS resolution is the main contributor to slow page fetches.

16.4

Confirm the Root Cause with ZDX Analysis

Cross-check the suspected DNS issue with automated score analysis.

Experience Center · find this resource

Search Menu → Analyze Score

  1. Return to ZDX Score Over Time and select Analyze Score for the affected interval.
  2. Review the highest-ranked contributing factor. Compare it with your DNS Resolve Time findings from Task 16.3.
  3. Summarize the evidence: the consistently Poor score, elevated DNS Resolve Time, and ZDX analysis. Avoid attributing an exact DNS server or latency value unless displayed in your current session.
✓
Expected result

Your diagnosis is supported by both user-level probe measurements and ZDX root-cause analysis.

✓
Lab 16 complete

Slow DNS confirmed as the root cause
