Lab 10

Add a Corporate Application

Build application segments and access policy, then enable ICMP for troubleshooting.

Time: ~35 minutesTasks: 3Outcome: Private app defined, restricted, and reachable
i
Use your assigned tenant

Use the Student ID, Student FQDN, session password, and Skytap link from your own lab-access email. Values shown in examples and screenshots are not your live credentials.

10.1

Configure a Wildcard Application Segment

Create a wildcard segment for discovery, attach it to segment/server groups, and allow access.

Current Experience Center navigation
Private Access›Policies›Access Control›Private Applications›Defined Application Segments

Fastest option: use Search menu and search for Access Policy.

  1. Open Private Access, then
    Policies›Access Control›Private Applications›Defined Application Segments
    Select Add Application Segment.
  2. Define the application:
    SettingValue
    NameDiscovery
    StatusEnabled
    Source IP AnchorDisabled
    Application*.patraining.safemarch.com
    TCP Ports2-52, 54-65535
    UDP Ports1-52, 54-65535
    TCP KeepaliveDisabled
    Double EncryptionDisabled
    BypassUse Client Forwarding Policy
    ICMP AccessDisabled
  3. Create Segment Group Discovered Apps (Enabled). Create Server Group CorpServers with Dynamic Server Discovery = Enabled and App Connector Group = OnPrem. Review and save.
  4. Open Private Access Access Policy (use Search menu for Access Policy). Add rule Discovered Apps, Action = Allow Access, criteria = Discovered Apps segment group, no additional criteria. Save.
  5. On Corp: Client PC browse to http://intranet.patraining.safemarch.com. Confirm the page loads and ZCC byte counters increase when you refresh.
✓
Expected result

Wildcard private applications are reachable through the OnPrem connector using the Discovered Apps access policy.

10.2

Configure User-Specific Access to the Intranet

Create a dedicated Intranet segment and restrict its allow policy to the student user.

Current Experience Center navigation
Private Access›Policies›Access Control›Private Applications›Defined Application Segments

Fastest option: use Search menu and search for Access Policy.

  1. In Experience Center search for Applications under Private Access analytics and locate intranet.patraining.safemarch.com in recently discovered applications. You can define it from discovery or create it directly from Defined Application Segments.
  2. Create:
    SettingValue
    Application Segment NameIntranet
    StatusEnabled
    Source IP AnchorDisabled
    Applicationintranet.patraining.safemarch.com
    Segment GroupCorpApps (Enabled)
    Server GroupCorpServers (existing)
    Leave unspecified settings at their defaults and save.
  3. Open Access Policy and add rule Allow Intranet, Action = Allow Access, application criteria = Intranet. Add user/session criterion loginname = student@<Student FQDN>. Save.
  4. On Corp: Client PC browse to http://intranet.patraining.safemarch.com and confirm the Student user can load the site. Refresh while watching ZCC traffic counters.
✓
Expected result

The dedicated Intranet application segment is accessible to the Student user through the Allow Intranet rule.

10.3

Enable ICMP Access

Enable ICMP on the Intranet application segment only for troubleshooting.

Current Experience Center navigation
Private Access›Policies›Access Control›Private Applications›Defined Application Segments
  1. On Corp: Client PC run ping intranet.patraining.safemarch.com. With ICMP Access disabled, the ping should fail.
  2. Open
    Private Access›Policies›Access Control›Private Applications›Defined Application Segments
    Edit Intranet, locate ICMP Access, set it to Enabled, and save.
  3. Run ping intranet.patraining.safemarch.com again. It should now receive replies.
i
Keep in mind

Enable ICMP only when it is useful for troubleshooting; it is not required for normal application access.

✓
Expected result

The intranet responds to ICMP after ICMP Access is enabled.

✓
Lab 10 complete

Private app defined, restricted, and reachable
