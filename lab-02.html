Configure User and Administrator Access Entitlements

Create identities, groups, and entitlements, then verify role-based access.

Time: ~40 minutesTasks: 4Outcome: Joe = limited/read-only; Bev = full admin

Technical concept

Administrative vs. Service Entitlements

Both are assigned to users or groups, but they grant two different kinds of access.

User / Group
→
Administrative Entitlement
→
Zscaler service + admin role
→
Admin-console permissions
User / Group
→
Service Entitlement
→
Subscribed Zscaler service
→
End-user service access
Administrative entitlement

What can this identity administer?

Assigns administrative access to a specific Zscaler service and pairs it with an admin role. The role determines what the administrator can view or change.

Service entitlement

Which service can this end user consume?

Assigns the user or group to a subscribed service such as Internet Access or Private Access. It does not by itself grant admin-console permissions.

i
How this maps to Lab 2

Joe receives read-only administrative access for ZIA/ZDX and a ZIA service entitlement. Bev is used to validate full administrative access. Keep the two concepts separate: administering a service and using a service are not the same permission.

2.1

Create Departments and User Groups

Create the organizational containers used later for entitlement assignment.

Current Experience Center navigation
Administration›Identity
  1. Open
    Administration›Identity›Departments
    Create Support (description: Support Department) and IT (description: IT Department). Save each department.
  2. Confirm both departments appear in the list.
  3. Open
    Administration›Identity›User Groups
    Select Add User Group, create Helpdesk L1, and save.
✓
Expected result

Support and IT exist, and the Helpdesk L1 group is available for assignment.

2.3

Add Administrative and Service Entitlements

Assign the administrative and end-user service entitlements required by the two test personas.

Current Experience Center navigation
Administration
  1. Open
    Administration›Admin Management›Role Based Access Control›Administrative Entitlements
    Choose Zscaler Internet Access → Assign Groups. Select Helpdesk L1 and assign the Executive Insights App role.
  2. Return to Administrative Entitlements, choose Zscaler Digital Experience → Assign Groups. Select Helpdesk L1 and assign ZDX Read-only Admin.
  3. Open
    Administration›Entitlements›End User Entitlements›Service Entitlements
    Choose Zscaler Internet Access → Assign Groups → Helpdesk L1 → Assign.
  4. Go to
    Administration›Identity›Users
    Open Joe → Entitlements and confirm ZIA/ZDX administrative entitlements plus the ZIA service entitlement. Optionally repeat for Bev.
i
Keep in mind

The predefined Executive Insights App role is used here as a convenient read-only ZIA role. In production, use a purpose-built role when appropriate.

✓
Expected result

Joe inherits read-only administration for ZIA/ZDX and a ZIA end-user service entitlement.

2.4

Validate Entitlement Access for Users

Validate that the permissions actually change what each persona can do.

Current Experience Center navigation
Administration
  1. Open a Chrome Incognito window and sign in to https://console.zscaler.com/ as joe@<Student FQDN> using Admin-123!. Confirm that Joe cannot access core administrative configuration and can only view the permitted ZIA/ZDX information. Sign out.
  2. In the same Incognito window, sign in as bev@<Student FQDN> using Admin-123!. Open
    Administration›Admin Management›Sign-On Policies
    Confirm Add Rule is enabled, then sign out.
  3. Open Zscaler Client Connector on Corp: Client PC and sign in as joe@<Student FQDN>. Verify Internet Security is ON, then sign out of ZCC.
✓
Expected result

Joe is restricted/read-only while Bev has administrator controls; Joe also receives ZIA service access.

✓
Lab 2 complete

Joe = limited/read-only; Bev = full admin
