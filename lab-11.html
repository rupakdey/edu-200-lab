Lab 11

Troubleshoot Access to an Internal Application for a Specific User

Diagnose Joe’s intranet access failure, restore his ZPA entitlement, and update the application access rule.

Time: ~25 minutesTasks: 2Outcome: ZPA entitlement and Intranet access-policy authorization verified
i
Use your assigned tenant

Use the Student ID, Student FQDN, session password, and CloudShare link from your own lab-access email. Values shown in examples and screenshots are not your live credentials.

11.1

Identify the Root Cause of the Internal Application Access Issue

Reproduce Joe’s failure, then check service entitlement and the Intranet access rule.

Experience Center · find this resource

Search Menu → Access Policy

  1. !
    Important — Use HTTP, not HTTPS

    Enter the full URL http://intranet.patraining.safemarch.com. Browsers may automatically switch a bare hostname to HTTPS (TCP 443), but the Intranet application segment in this lab is configured for HTTP (TCP 80). If the address bar shows https://, change it back to http:// before testing. An HTTPS failure here does not necessarily indicate a ZPA access-policy problem.

    On Corp Client PC sign in to ZCC as joe@<Student FQDN> using the password created in Lab 2. Browse to http://intranet.patraining.safemarch.com and confirm access fails.
  2. Open Search Menu → Users Find Joe, open the user, and review Entitlements.
  3. Confirm Joe has ZIA through Helpdesk L1 but does not have the ZPA/Private Access service entitlement.
i
Two checks, not one

Joe must have both an active ZPA service entitlement and an access policy that allows him to the specific Intranet application segment. The wildcard Discovery rule does not automatically authorize Joe for the more specific application.

✓
Expected result

Joe is missing the ZPA service entitlement and is not included in the existing Allow Intranet access rule.

11.2

Resolve the Internal Application Access Issue

Assign Joe’s ZPA entitlement, add him to the existing Allow Intranet rule, then verify access.

Experience Center · find this resource
Policies›Access Control›Private Applications›Access Policy

Search Menu → Access Policy

Zscaler Help: Editing Access Policies

  1. Open Search Menu → Service Entitlements Select Zscaler Private Access → Users → Assign Users → select Joe → Next → Assign.
  2. Verify Joe now receives the Private Access/ZPA service entitlement.
  3. On Corp Client PC open ZCC and choose Update Policy. Confirm Private Access becomes visible/active.
  4. Update the existing Allow Intranet access policy to include Joe. In Experience Center, open Search Menu → Access Policy (or follow the path above). Find Allow Intranet and select Edit.
    SettingRequired configuration
    RuleAllow Intranet (edit the existing rule)
    ActionAllow Access (unchanged)
    ApplicationsIntranet application segment (unchanged)
    User attributeloginname: allow student@<Student FQDN> OR joe@<Student FQDN>
    In the user attribute criteria, add Joe as an alternative permitted login, without removing the existing Student login. If the condition builder displays Boolean logic, verify that the usernames are combined with OR / Any rather than an AND / All condition. Save the rule.
    i
    Why this step is required

    ZPA service entitlement enables Joe to use Private Access; the Allow Intranet access policy determines whether Joe may open this specific application. Both must permit access.

  5. !
    Important — Use HTTP, not HTTPS

    Enter the full URL http://intranet.patraining.safemarch.com. Browsers may automatically switch a bare hostname to HTTPS (TCP 443), but the Intranet application segment in this lab is configured for HTTP (TCP 80). If the address bar shows https://, change it back to http:// before testing. An HTTPS failure here does not necessarily indicate a ZPA access-policy problem.

    Browse again to http://intranet.patraining.safemarch.com and confirm the page loads with Joe signed in, after the access-rule change.
✓
Expected result

Joe has a ZPA service entitlement, the Allow Intranet rule permits Student OR Joe, and the intranet page loads for Joe.

✓
Lab 11 complete

Missing ZPA entitlement found and corrected
