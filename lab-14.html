Navigate the Incident, Self-Service, Application Overview Dashboards

Use the read-only Solutions Demo Center to inspect performance, incident, application, and user views.

Time: ~20 minutesTasks: 4Outcome: Key ZDX dashboards and drill-downs understoodEnvironment: SDC · read-only

Solutions Demo Center — read only

Labs 14–16 use the pre-configured SDC tenant, not your learner tenant. Complete the SDC access checkpoint before continuing. Do not create or modify configuration unless a lab step explicitly instructs you to.

14.1

View ZDX Performance Dashboard

Use the read-only SDC tenant to explore the ZDX performance dashboard and geographic drill-downs.

Experience Center · find this resource

Search Menu → Map View

  1. Complete the SDC Access checkpoint first. Sign in with the SDC Admin Username and Password from your session email and complete any required 2FA enrollment.
  2. Open Digital Experience. Use Search menu for Map View / the Performance dashboard if needed. Set the reporting interval to 24 Hours.
  3. Review Most Impacted Applications. Open an application such as ZPA Application and inspect its performance metrics.
  4. In Regions by ZDX Score, click locations, zoom, use Draw Fence → Filter Selection, then Reset the map.
  5. Review ZDX Score details and use Add Another Application to compare another application. Try Geolocation and other filters such as Departments, Zscaler Locations, User Groups, Location Groups, Last Mile ISPs, and OS.
  6. Open the Wi-Fi Dashboard and review total access points, AP Wi-Fi performance, and connected devices.
i
Keep in mind

SDC data is simulated/preconfigured. Exact scores, locations, and application names can vary from screenshots.

✓
Expected result

You can navigate the SDC performance dashboards and use filters/drill-downs without changing configuration.

14.2

View Incidents and Self Service Dashboards

Review incident and self-service views in the SDC dataset.

Experience Center · find this resource

Search Menu → Incidents

  1. In Digital Experience use Search menu for Incident Dashboard. Review incident summaries and categories.
  2. Scroll to Incidents by Epicenters, select a marker, open an incident, then choose View Incident Details to inspect collected metrics.
  3. Use Search menu for Self Service Dashboard and review notification/summary graphs for the selected timeframe.
i
Keep in mind

If the Incidents by Epicenters panel reports “Try again later,” refresh once and retry.

✓
Expected result

You can move from high-level incidents to affected epicenters/details and review Self-Service trends.

14.3

View Application Overview Dashboard

Use the application overview to find the worst-performing application and inspect impact dimensions.

Experience Center · find this resource

Search Menu → Applications Overview

  1. In Digital Experience use Search menu for Applications.
  2. Sort the application table by ZDX Score Trend and open an application with a low score.
  3. In ZDX Score Over Time, drag across a period with a significant change to zoom in; use Zoom out when finished.
  4. Review impacted Meetings (where applicable), Regions, Zscaler Locations, and the application Probe Status.
✓
Expected result

You can identify a poor application interval and see the dimensions/probes associated with it.

14.4

View User Overview Dashboard

Drill into an affected user and compare device, web-probe, and cloud-path telemetry.

Experience Center · find this resource

Search Menu → Users Overview

  1. In Digital Experience open Users. Select an application and Apply.
  2. Filter ZDX Score by Poor or Okay, then open an affected user.
  3. Review OS, IP, and device context. Open View More Device Details and inspect Hardware, Network, and Software tabs.
  4. Review the user’s ZDX Score Over Time, then Web Probe Metrics. Click graph samples to inspect Page Fetch Time, Server Response Time, and related metrics.
  5. Review Cloud Path Probe Metrics for latency and packet loss. Expand Hop View for the leg with the largest latency differential and use Command Line View to identify high-loss/high-latency hops.
i
Keep in mind

ZDX troubleshooting is probe-driven: probes provide baseline and real-time measurements that let you localize an issue instead of relying only on user symptoms.

✓
Expected result

You can correlate the user’s score with device context, web probes, and hop-by-hop path metrics.

✓
