How Zscaler Private Access fits together

This explainer is intentionally broader than Lab 9. Use it as the conceptual foundation for provisioning infrastructure in Lab 9, publishing applications and access policy in Lab 10, and troubleshooting the same access chain in Lab 11.

Scope: Labs 9–11Focus: access flow + configuration objectsGoal: understand the objects before configuring them
Core idea

ZPA connects an authorized user to an allowed private application

ZPA provides application-specific access rather than general routed access to the private network. Identity and access policy govern each connection, while the user-side Client Connector and customer-side App Connector establish outbound connections to the ZPA service.

1 · User side

Client Connector

Intercepts a request for the private application from an authenticated user/device and establishes the user-side connection to the ZPA service.

2 · ZPA cloud

Service Edge / broker

Enforces the access policy and joins the authorized user-side and connector-side connections for the permitted application.

3 · Application side

App Connector

Initiates its own outbound connection to ZPA, resolves private DNS, and reaches the permitted backend application. It does not require an inbound listener.

DNS and addressing

Why the endpoint does not need the real backend IP

For hostname-based access, Client Connector can present a synthetic IP on the client side. ZPA maps that intercepted request to the permitted application, while the App Connector resolves and reaches the real private backend from the application side.

i
Synthetic IP is an abstraction

The synthetic-IP view separates the endpoint from the backend addressing used inside the private environment. The App Connector still needs working reachability and DNS resolution to the real application.

Configuration model

How the main ZPA objects relate

These relationships describe configuration dependencies—not packet hops. Keeping the objects distinct makes Labs 9–11 much easier to follow.

Segment group

Groups application segments

Provides a policy-targeting container for related applications.

→
Application segment

Defines the application destination

FQDN/IP plus TCP/UDP ports. This is the application the user is trying to reach.

→
Server group

Maps backend reachability

Groups backend servers and associates the application with the connector-side reachability.

→
App Connector group

Selects a connector pool

Groups App Connectors that share application reachability.

→
App Connectors

Provide application connectivity

Deployed connector instances that establish outbound connectivity and reach the backend.

Access policy

Who may access what?

Evaluates the user/group, device posture and application criteria. A policy can target an application segment or segment group.

Provisioning key

Enrollment credential

Used when enrolling a new App Connector into the tenant and its App Connector group. It is an enrollment mechanism—not an application access policy.
