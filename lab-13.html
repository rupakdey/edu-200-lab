13.1

Verify Access to the Internal Application Using RDP

Allow RDP through the Intranet application segment, connect to the Windows server, and review diagnostics.

Current Experience Center navigation
Private Access›Policies›Access Control›Private Applications›Defined Application Segments

Fastest option: use Search menu and search for Private Applications.

  1. Open
    Private Access›Policies›Access Control›Private Applications›Defined Application Segments
    Edit Intranet and add TCP 3389 to its port ranges. Save.
  2. On Corp: Client PC open Remote Desktop Connection and connect to intranet.patraining.safemarch.com as student / Admin-123!. Confirm the desktop session opens.
  3. Run netstat -fn and verify an Established connection on port 3389.
  4. Use Experience Center search for Private Applications analytics. Find intranet.patraining.safemarch.com:3389 under recently accessed applications and open diagnostics.
  5. Optional troubleshooting: remove TCP/UDP 3389 from the application segment, retry RDP, then return to Private Applications analytics → Top Policy Blocks / Access Policy Blocks → Show in Logs. Review Status Code, Server IP, and Protocol. Restore the port afterward if you want to leave the environment working.
✓
Expected result

RDP succeeds when 3389 is defined in the application segment; removing the port reproduces a visible access failure.
