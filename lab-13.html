Verify Access to Internal Application Using RDP

Connect to the internal Windows server through RDP over ZPA and validate the session.

Official documentation: Defined Application Segments

  1. Open
    Private Access›Private Applications›Application Segments
    Edit Intranet and add TCP 3389 to its port ranges. Save.
  2. On Corp Client PC open Remote Desktop Connection and connect to intranet.patraining.safemarch.com as student / Admin-123!. Confirm the desktop session opens.

  3. Keep the RDP connection open. On the Corp Client PC (not inside the remote desktop), open Command Prompt and run netstat -fn.

    Find a TCP session with Foreign Address ending in :3389 and State = ESTABLISHED. In the example, the destination is 100.64.1.1:3389, a ZPA/ZCC virtual address rather than the server’s actual private IP. The address and client-side source port may differ in your session.

  4. In the ZPA Admin Portal, open Private Access → Dashboards → Applications. In Recent Applications Accessed, look for intranet.patraining.safemarch.com:3389 and confirm the test connection is represented. Select an appropriate recent time range; dashboard reporting may take time to update.

i
Technical context — Why a missing port may produce no ZPA block log

If TCP 3389 is missing from the matched Intranet application segment, Zscaler Client Connector (ZCC) may drop the connection before it reaches ZPA cloud access-policy evaluation. Consequently, no corresponding ZPA Access Policy Block event is guaranteed to exist. An absent policy-block record does not prove that access was authorized.

✓
Expected result

The RDP desktop opens successfully, the Corp Client PC shows an ESTABLISHED TCP connection to destination port 3389, and the ZPA Applications dashboard shows recent activity for intranet.patraining.safemarch.com:3389 (subject to reporting delay).
