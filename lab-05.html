Technical concept

What SSL/TLS inspection is doing

HTTPS protects data in transit, but encryption also hides content from security controls. ZIA TLS inspection creates two encrypted sessions so it can decrypt, inspect, apply policy, and then re-encrypt the traffic.

User / browserTrusts the inspection CA
TLS session 1→
ZIA Service EdgeDecrypt → inspect → enforce → re-encrypt
TLS session 2→
DestinationOriginal server certificate
Why inspect?

Security needs visibility

Inspection lets ZIA evaluate encrypted web traffic for threats, data protection, and other content-aware policies.

Certificates

The endpoint must trust the inspection CA

ZIA presents a dynamically issued inspection certificate to the client. In this lab, Client Connector deploys the trusted Zscaler CA according to the App Profile.

Certificate pinning

Some apps reject replacement certificates

A pinned application expects a specific certificate or key. The ZIA-issued inspection certificate does not match, so the app may fail. The normal fix is a targeted Do Not Inspect rule, not a broad bypass.

5.1

Enable SSL/TLS Inspection for All Destinations

Turn on TLS inspection for encrypted traffic and confirm the certificate chain changes.

Current Experience Center navigation
Internet Access›Policy›SSL/TLS Inspection
  1. Before the policy change, open an Incognito Chrome window to https://www.wikipedia.org and inspect the site certificate. Note the original server certificate issuer.
  2. Open
    Internet Access›Policy›SSL/TLS Inspection
    Select Add SSL Inspection Rule.
  3. Configure Rule Order 1, Rule Name SSL Inspect All, and Action Inspect. Save and Activate.
  4. Close/reopen Incognito (or refresh), revisit Wikipedia, and inspect the certificate again. It should now be signed through Zscaler.
✓
Expected result

HTTPS traffic matches SSL Inspect All and the browser sees a Zscaler-issued inspection certificate.

5.2

Verify Zscaler CA Installation [Optional]

Optionally verify that the Windows trust store contains the Zscaler root certificate.

  1. Open certmgr from Windows Search or Command Prompt.
  2. Go to Trusted Root Certification Authorities → Certificates and verify the Zscaler Root CA exists and is not expired.
  3. Optionally open chrome://certificate-manager/ → Local certificates → View imported certificates from Windows and confirm the same trust anchor.
i
Keep in mind

Zscaler Client Connector installs the root CA according to the app-profile settings used in this lab.

✓
Expected result

The Zscaler Root CA is trusted by Windows/Chrome.

5.3

Review Certificate Pinning Errors

Reproduce a certificate-pinning failure, bypass inspection only for the affected application, then verify the transaction logs.

Current Experience Center navigation
Internet Access›Policy›SSL/TLS Inspection

Fastest option: use Search menu and search for Web Insights.

  1. On Corp: Client PC download Threema Private Desktop for Windows from https://threema.com/en/download.
  2. Install the downloaded MSIX from PowerShell with Add-AppxPackage -Path .\Downloads\threema-desktop-latest-windows-x64.msix and open Threema Beta. Observe the connection/install error while TLS inspection is active.
  3. Open
    Internet Access›Policy›SSL/TLS Inspection
    Add a rule at order 1 named Bypass Threema. Under Cloud Applications choose Instant Messaging → Threema; set Action to Do Not Inspect. Save and Activate.
  4. End any running Threema process in Task Manager and reopen Threema Beta. The app should now work without the pinning failure.
  5. Use the Experience Center search for Web Insights. Query the last hour and compare SSL Inspected vs Bypassed Transaction events. Allow several minutes for logs to appear.
i
Keep in mind

Bypass only the application that requires it; do not weaken inspection more broadly than necessary.

✓
Expected result

Threema works when bypassed, and Web Insights shows both inspected and bypassed TLS transactions.

✓
