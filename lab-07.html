Lab 7

Configure DNS Security

Steer DNS through Zscaler, create DNS policy, and verify enforcement in DNS insights.

Time: ~20 minutesTasks: 3Outcome: Gambling DNS requests blocked and logged
Technical context · ZCC DNS processing

Why DNS must reach Zscaler before a DNS policy can work

DNS normally translates a domain name into an IP address before the connection begins. Blocking risky or prohibited domains at this stage can prevent an unwanted connection early—but only when the DNS request is sent through the policy enforcement path.

How Zscaler Client Connector chooses a DNS path

For a Windows App Profile using Z-Tunnel 2.0, ZCC evaluates several conditions, not just the domain name. Depending on the private application definition, DNS resolver exclusions, and Domain Inclusion/Exclusion configuration, the request may be handled through ZPA, ZIA, or a device/network DNS resolver.

SituationResult
ZPA private applicationMatching private application domains are handled by ZCC/ZPA; the application may receive a synthetic IP address.
DNS request eligible for ZIA steeringThe query is tunneled to a ZIA Service Edge, where the configured DNS Control policy can apply.
DNS server excluded from Z-Tunnel 2.0ZCC evaluates the App Profile's Domain Inclusion/Exclusion rules; effective exclusions or no inclusion match use the device/network DNS resolver.

Domain-rule precedence, IPv4/IPv6 DNS server exclusions, and the assigned ZCC/App Profile version can affect the final decision. The diagram shows the general decision logic rather than every implementation edge case.

What the next three tasks demonstrate

TaskPurpose
7.1 · Steer DNSAdd the wildcard * to Domain Inclusion, directing eligible DNS requests through Z-Tunnel 2.0 toward ZIA.
7.2 · Enforce DNS policyCreate the Block Gambling DNS Control rule to restrict lookups for that category.
7.3 · Verify enforcementUse DNS Insights to confirm that the requests reached Zscaler and matched the intended rule.

Key distinction: ZCC decides where eligible DNS requests are sent; ZIA enforces the DNS Control policy on requests that reach it. Adding * does not override private application handling or every DNS exclusion.

Official references: ZCC App Profiles · DNS Control policy guidance.

7.1

Configure App Profile

Update the existing Windows app profile so all DNS domains are included for Zscaler DNS steering.

Experience Center · find this resource

Search Menu → Windows App Profile

  1. Open Search Menu → Windows Edit the HandsOnLab Windows policy.
  2. Under Traffic Steering → DNS, add * to Domain Inclusion, choose Create "*", and save.
  3. On Corp Client PC open ZCC → More → Update Policy.
✓
Expected result

The Windows policy includes all DNS domains and the endpoint has refreshed its policy.

7.2

Configure a DNS Control Policy

Create a DNS rule that blocks the Gambling category.

Experience Center · find this resource
Internet Access›Policy›DNS Control

Search Menu → DNS Control

Official documentation: DNS Control Policy

  1. Before the change, run nslookup www.gambling.com and confirm it resolves.
  2. Open
    Internet Access›Policy›DNS Control
    Review the predefined rules, then select Add DNS Filtering Rule.
  3. Configure:
    SettingValue
    Rule Order1
    Rule NameBlock Gambling
    Rule StatusEnabled
    DNS Request CategoriesGambling
    DNS Response CategoriesGambling
    Network TrafficBlock
    Save and Activate.
  4. Run nslookup www.google.com and confirm normal DNS still works. Then run ipconfig /flushdns followed by nslookup www.gambling.com 8.8.8.8. The gambling lookup should time out/fail.
✓
Expected result

Legitimate DNS resolves; gambling-category DNS is blocked.

7.3

View DNS Insight Logs

Confirm that the DNS policy hit is visible in logging/insights.

Experience Center · find this resource

Search Menu → DNS Insights

  1. Use Search menu to open DNS Insights (or the DNS logs view available in Data Explorer).
  2. Set Timeframe to Current Day, add filter Rule Name = Block Gambling, and apply the filter.
  3. Verify gambling-domain requests are associated with the Block Gambling rule and a blocking action. If no events appear immediately, continue and return after log ingestion.
i
Keep in mind

DNS log ingestion may take roughly 15 minutes in the lab tenant.

✓
Expected result

DNS Insights shows hits on the Block Gambling rule.

✓
Lab 7 complete

Gambling DNS requests blocked and logged
