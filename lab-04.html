Lab 4

Configure Firewall Filtering Policy

Observe the default block, allow required non-web traffic, and restrict an application.

Time: ~25 minutesTasks: 3Outcome: ICMP/SSH allowed; WhatsApp blocked

Use your assigned tenant

Use the Student ID, Student FQDN, session password, and CloudShare link from your own lab-access email. Values shown in examples and screenshots are not your live credentials.

4.1

Test Non-Web Traffic with the Default Firewall Block

Confirm that the default firewall behavior blocks unmatched non-web traffic.

Experience Center · find this resource

Search Menu → Firewall Control

  1. Open
    Internet Access›Policy›Firewall Control
    Verify the Default Rule is Block/Drop and that no earlier rule permits the ICMP/SSH tests used below.
  2. On Corp Client PC run ping www.google.com. The request should time out.
  3. Open PuTTY, set Host Name to github.com, and click Open. The outbound SSH connection should time out/fail.
  4. Close PuTTY and Command Prompt.
✓
Expected result

ICMP and SSH fail because they fall through to the default Block/Drop rule.

4.2

Configure Firewall Policy to Allow Outbound SSH and ICMP Traffic

Add one rule that allows outbound ICMP and SSH for the student user.

Experience Center · find this resource
Internet Access›Policy›Firewall Control

Search Menu → Firewall Control

Official documentation: Firewall Filtering

  1. In
    Internet Access›Policy›Firewall Control
    select Add Firewall Filtering Rule.
  2. Configure:
    SettingValue
    Rule Order1
    Rule StatusEnabled
    Rule NameICMP_SSH
    UserStudent Admin
    Network ServicesICMP, SSH
    Network TrafficAllow
    Save and Activate.
  3. On Corp Client PC run ping www.google.com again. It should now receive replies.
  4. Open PuTTY to github.com. A server-key/login prompt is enough to prove TCP/22 is reaching the destination; you do not need to authenticate.
✓
Expected result

ICMP succeeds and PuTTY reaches the SSH server.

4.3

Configure a Firewall Filtering Policy to Restrict Applications

Block WhatsApp at the firewall/application layer while leaving the ICMP/SSH allow rule in place.

Experience Center · find this resource
Internet Access›Policy›Firewall Control

Search Menu → Firewall Control

Official documentation: Firewall Filtering

  1. In
    Internet Access›Policy›Firewall Control
    add a Firewall Filtering Rule.
  2. Configure:
    SettingValue
    Rule Order2
    Rule StatusEnabled
    Rule NameRestrict_Whatsapp
    UserStudent Admin
    Network ApplicationWhatsApp
    Network TrafficBlock/Drop
    Save and Activate.
  3. Browse to https://web.whatsapp.com and confirm access is restricted.
i
Keep in mind

A URL policy can block the web site, but a firewall application rule can also cover non-browser WhatsApp traffic.

✓
Expected result

WhatsApp is blocked by the firewall rule.

✓
Lab 4 complete

ICMP/SSH allowed; WhatsApp blocked
