Technical explainer

App Profile vs. Forwarding Profile

These two Client Connector objects work together but solve different problems. The App Profile determines which endpoint settings a user or device receives; it then references a Forwarding Profile, which determines how traffic is handled in different network contexts.

Endpoint configuration

App Profile

Think of this as the policy package for the Client Connector application on the endpoint.

  • Assignment: OS-specific rule, user/group scope, and rule precedence.
  • Traffic steering: PAC behavior plus application or IP bypasses.
  • Endpoint controls: certificate installation and protection settings such as logout, disable, or uninstall controls.
  • Operations: logging and other app-level settings.
  • Important: the App Profile selects the Forwarding Profile the endpoint should use.
Traffic handling

Forwarding Profile

This object answers a different question: how should traffic flow on this network?

  • Defines behavior for network contexts such as On-Trusted, Off-Trusted, VPN-Trusted, and Split VPN-Trusted.
  • Controls the ZIA forwarding mode and whether ZPA traffic is tunneled or not.
  • For ZIA, the selected tunnel version determines the transport used to send traffic to Zscaler.
  • Z-Tunnel 1.0: CONNECT-based forwarding for proxy-aware/web traffic depending on mode.
  • Z-Tunnel 2.0: packet tunnel over DTLS/TLS and supports all ports and protocols, subject to policy and bypasses.
i
How this maps to Lab 3

You will first create the HandsOnLab Forwarding Profile and set ZIA to Z-Tunnel 2.0. You will then create the Windows App Profile and point it to that Forwarding Profile. This distinction matters later because the firewall exercises require non-web traffic to reach ZIA for inspection.

3.1

Configure Traffic Forwarding Options

Create a forwarding profile and Windows app profile so endpoint traffic is tunneled to the Zero Trust Exchange.

Current Experience Center navigation
Infrastructure›Connectors›Client
  1. Sign in at https://console.zscaler.com/ with the student administrator account.
  2. Open
    Infrastructure›Connectors›Client›Forwarding Profile for Platforms
    Select Add Forwarding Profile and name it HandsOnLab.
  3. For Windows Driver Selection choose Packet Filter Based. Under ZIA set On-Trusted Network to Tunnel with Z-Tunnel 2.0; set VPN Trusted and Off-Trusted to Same as On-Trusted Network.
  4. Under ZPA, set On-Trusted Network to Tunnel and use Same as On-Trusted Network for VPN Trusted and Off-Trusted. Save.
  5. Open
    Infrastructure›Connectors›Client›Platform Settings›Windows
    Under App Profile select Add Windows Policy and configure:
    SettingValue
    NameHandsOnLab
    Rule Order1
    StatusEnable
    Forwarding ProfileHandsOnLab
    Install Zscaler SSL CertificateOn
    User GroupsAll
    Click Add.
i
Keep in mind

Z-Tunnel 2.0 is required here because the later firewall exercises depend on all ports/protocols being forwarded to ZIA.

✓
Expected result

The HandsOnLab forwarding profile and Windows app profile are enabled and assigned to all users.

3.2

Sign In to Zscaler Client Connector and Verify Protection

Sign in to ZCC and verify that the expected services and policy are active.

  1. On Corp: Client PC, open Zscaler Client Connector from the system tray and sign in as student@<Student FQDN> with the password set in Lab 1.
  2. On Private Access, verify Service Status = ON and that Client/Broker IP information is populated.
  3. On Internet Security, verify Service Status = ON, the username is correct, and byte counters increase as pages load.
  4. On Digital Experience, verify Service Status = ON and Authentication Status = Authenticated.
  5. On More, verify the applied App Policy is HandsOnLab. If not, click Update Policy and recheck.
  6. Browse to https://ip.zscaler.com and confirm traffic is being serviced by a nearby Zscaler Service Edge.
i
Keep in mind

If ZPA or ZDX is missing, check the student user under Administration → Identity → Users → Entitlements.

✓
Expected result

ZIA, ZPA, and ZDX are active in ZCC; the HandsOnLab policy is applied; internet traffic is forwarded through Zscaler.
